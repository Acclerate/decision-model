# grill-decision：选项评分卡（配合 grilling / grill-me）

## 定位与分工

- **grilling**（grill-me 的本体）负责**挖出**决策树、质询证据、收敛选项——它产出事实与约束，要求每轮给"➡️ 推荐答案"；
- **decision-model MCP** 负责**算出**校准的概率与分值（choice/noul/score）；
- **本 skill** 负责**组合**：把质询证据结构化为 state → 对每个选项批量评分 → 判别分数 + 统计分类 → 反哺下一轮质询。

一句话：grilling 问"为什么"，本 skill 算"差多少"，两者循环。

## 触发时机

1. grilling 会话中，某决策节点收敛出 ≥2 个候选选项，且其父节点决策已 settled；
2. 一轮质询结束，需要为"➡️ 推荐答案"提供量化依据时；
3. 用户明确要求"给选项打分 / 评分卡 / 判别分数 / 量化每个选项"。

## 工作流（6 步）

### ① 证据 → state

把该节点**之上**的 settled 决策与环境事实写成 state。模板：

```json
{
  "decision": "要决定什么（节点问题）",
  "constraints": ["硬约束，逐条列出"],
  "facts": ["质询与环境得到的事实，逐条列出"],
  "history": ["相关历史教训，如有"]
}
```

规则：只写已证事实；**用户在质询中给出的答案是最强证据**；每个选项的证据必须对等（不能 A 有三条、B 只有一条——证据不对等的评分不可比）。

### ② 每选项 5 问 + 全局 1 问（一次 decide 批量）

问题 id 命名 `<维度>__<选项id>`，全部放进**同一次 `decide` 调用**（同一 state、并行前向、批量不加延迟）：

| 问题 id 模板 | type | instructions |
|---|---|---|
| `viability__<opt>` | noul | 选项「<描述>」在上述约束与事实下是否可行 |
| `fatal_flaw__<opt>` | noul | 选项「<描述>」是否存在足以否决它的致命缺陷 |
| `risk__<opt>` | score | 选项「<描述>」的风险程度。criteria：`["低风险，成熟方案", "可控风险，需注意边界", "较高风险，需额外投入缓解", "高风险，已知会出问题"]` |
| `cost__<opt>` | score | 选项「<描述>」的改造成本。criteria：`["几乎零改造", "小改造，人天内", "中等改造，周级", "大改造，多周或架构级"]` |
| `fit__<opt>` | score | 选项「<描述>」与核心约束的契合度。criteria：`["不契合核心约束", "部分契合", "大部分契合", "完全契合"]` |

再加一问全局交叉校验：

```
final_pick = { "type": "choice", "instructions": "综合全部证据与约束，应该选择哪个选项",
               "criteria": { <每个选项: 描述>, "other": "以上都不是" } }
```

规模：3 选项 = 16 问（正好批量推荐上限）；4 选项 = 21 问可接受；更多选项先粗筛再评。

### ③ 判别分数 D（0-100，确定性公式）

```
D_i = 100 × ( 0.30·P可行 + 0.25·(1 − P致命) + 0.20·fit/3 + 0.15·(1 − risk/3) + 0.10·(1 − cost/3) )
```

- 权重是默认值，可在会话开头按业务调整（成本敏感 → cost 提到 0.20 并等比下调其他），但**同一决策内必须恒定**，否则分档不可比；
- score 维度取 `score` 字段（期望值），**不要用 score 的 confidence 参与排序**——实测 score 的 confidence 口径与 choice 不同；
- noul 直接用 P 值。

### ④ 统计分类（分档）

| 判别分 D | 分类 |
|---|---|
| ≥ 75 | 推荐 |
| 60 – 74.9 | 可行 · 需复核 |
| 45 – 59.9 | 存疑 |
| < 45 | 排除 |

- **硬否决**：`P致命 ≥ 0.8` → 该选项直接标"建议排除"，无论 D 多高；
- **行级策略**：`P可行 ∈ (0.5, 0.8)` 或 `P致命 > 0.5` → 该行标"复核"（阈值策略与 decision skill 第 6 节一致）。

### ⑤ 全局交叉校验

`final_pick` 的 top 选项与 D 最高项**不一致 → 全表强制复核**。这是校准信号：说明权重或证据有偏，不要直接取 D 最高项，也不要直接取 final_pick——先补证据再重评。

### ⑥ 反哺 grilling

低 margin 项（P ∈ 0.5~0.8）对应的缺失证据，转成下一轮 frontier 问题。评分卡末尾必须回答："要拉开判别差距，下一轮该质询什么？"

## 输出模板

```markdown
## 决策节点：<名称>

state 摘要：<约束 N 条 / 事实 N 条>

| 选项 | 可行性 P | 致命缺陷 P | 风险 | 成本 | 契合 | 判别分 D | 分类 | 策略 |
|---|---|---|---|---|---|---|---|---|
| jwt | 0.87 | 0.31 | 1.4 | 0.9 | 2.1 | 68.2 | 可行·需复核 | 复核 |
| … |

交叉校验：final_pick = <opt>（与 D 最高项<一致 / 不一致 → 全表复核>）
➡️ 建议：<选项>（D=xx）；下一轮质询建议：Q…
```

输出后按 grilling 规则**等待用户确认**，评分卡是依据，不替代用户决策。

## 注意事项

- 同一决策内不要中途改问题定义（id/类型/instructions/criteria）——改了就分布漂移，前后不可比；
- state 缺关键事实时先跑质询补证据，不要拿"不知道"去评；
- 每次评分留痕：把 state 摘要与评分卡写入会议纪要/ADR（grill-with-docs 用户可直接作为 ADR 附件）。
